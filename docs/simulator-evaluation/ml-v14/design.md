# Chronological learned combination and chip specialization

The accepted model remains v13. This experiment tests the user's 90% recall / 97% precision objective with new chronological learned models. It does not automatically accept or activate a successor. The source is repeatedly exposed synthetic IBM history, not independent confirmation.

For each existing six-month fit window, train current EBM and CatBoost experts on the first three months. Score every transaction in the later three months without fitting on its labels; build account score-history features before sampling. Fit second-stage models on the later-quarter labels using the established deterministic negative sample, all frauds and inverse inclusion weights. This is a chronological stacking holdout, not ordinary shuffled cross-validation. Experts remain frozen afterward so inference does not silently shift from out-of-time scores to refitted-model scores.

A separate online expert is fitted to Jan-Mar2016, before every stacking block. Recent stacking blocks have zero online frauds, so include the Apr-Jun2016 stacking block in the 2018 second-stage training sets. Retain historical base predictions for that historical block; never apply a 2018-fitted expert backward to it. Current calibration remains strictly after every second-stage training block and uses validation-role users disjoint from all fitting users. No historical calibration of a more recent combiner is allowed. All windows retain complete unlabelled event histories before training-row sampling.

Compare an otherwise identical combiner with and without prior expert-score sequence features, at fixed modest capacity. Sequence features summarize same-instrument strictly earlier scores over one hour, one day and seven days, plus last scores and time since positive scores. Equal-time transactions cannot see each other. Features contain neither fraud labels nor investigator-confirmation assumptions. State resets for each stacking, calibration and evaluation interval, matching earlier conservative boundary behavior. Original delayed-feedback features retain their declared 30-day fit-role-label assumption; no new immediate feedback channel is introduced.

Train a chip-only sequence specialist with extra weight on difficult legitimate training rows, selected from out-of-time base scores within each training block. Direct policies can reject incumbent alerts; additive policies retain them and optimize a joint 97% calibration precision constraint. Include all six frozen candidates and a matched flat/sequence ablation. Test complete score ties, unsupported thresholds and combined budget enforcement.

Use one predeclared seed for this bounded pilot, two computation threads and the existing 2.5 GiB process budget. Report single-seed training uncertainty as unmeasured. This is not a large model search. The protocol fixes exact hyperparameters, target/upgrade criteria and selection before evaluation. Evaluate the complete natural-prevalence cohorts for all three periods, with paired customer uncertainty and per-period/channel confusion counts. Only claim consistent 90/97 attainment if it holds in every period; also report pooled-only attainment separately. The latest full-incumbent follow-through uses the already frozen new models and a frozen selected method, compared against the full accepted v13 on the same rows. It is descriptive and not an additional independent cohort.

All earlier sources, models, reports, plans and personal reminders stay immutable. New model packages and derived records live under ignored training_data/ml-v14. Record chronology, feature/source hashes, fitting identities, parameters, weights, frozen predictions before outcome joins, and all failures. Exact serialized-score replay and an independent history calculator must validate the implemented sequence semantics. No production application or external-data change is included.
