# ML v2 frozen experiment design

V2 tests better model selection and gradual, recency-weighted personalization using the existing IBM source. V1 code, artifacts and its consumed June 2018 evaluation remain unchanged. The user authorized implementation and evaluation; this experiment does not silently activate a model in the application.

The label-blind date audit found coverage from January 1991 through February 2020. Only development-user outcomes were inspected for the broader support audit. The original reserved-user membership remains excluded from supervised fitting. All 2019 outcomes for those users remain reserved until final prediction freeze. Previously inspected reserved June 2018 outcomes are not a v2 evaluation or selection population.

Extraction covers October 2017 through December 2019. Two chronological development folds train on January–June 2018 and April–September 2018 respectively, then evaluate July–September and October–December on the separate internal-validation users. Both folds have a complete preceding 90-day context where source history exists. Final models all fit the same July–December 2018 development population. Final evaluation is the entire year 2019 for reserved users, with histories updated using prior unlabelled observations. The six-month supervised windows limit memory; v2 does not claim that more fitting rows alone caused improvement.

Model selection averages the two quarterly recalls at 1% capacity, breaking ties by worst-quarter recall then mean average precision. Each model family receives two fixed configurations on standard features. Its selected configuration is then held identical for the hard-fallback and soft-history ablations. Candidate selection compares the resulting six family/feature combinations and a standard logistic reference. No configuration changes, seed selection, post-test candidate replacement or test-period expansion are allowed after reserved scoring.

CatBoost configurations are 200 trees/depth 5/L2 3 and 350 trees/depth 6/L2 10, both learning rate 0.06. EBM configurations are 256 rounds/5 interactions and 512 rounds/10 interactions, learning rate 0.05; no internal validation or early stopping can expose future periods. Logistic C=1 remains fixed. Feature engineering parameters are predeclared, not searched. All models run sequentially, two training threads. The measured available memory was 3.29 GiB; the process budget is 2.5 GiB. Runtime measurements and any resource failure must be reported without silently dropping target rows.

Support requirements: each initial fit needs 100 frauds/20 users; each selection fold needs 30 frauds/5 users; the final reserved comparison needs 100 frauds/20 users. Channel-specific claims require 30 frauds/10 users per channel. Empty or sparse segments retain undefined or explicitly inconclusive results. No support rule is relaxed after outcomes are opened.

Primary comparisons are the development-selected candidate versus R0 and versus the tuned standard CatBoost comparator. Eligibility requires at least five percentage points higher recall at 1%, a positive lower paired 95% user-cluster interval, no average-precision point regression, no coverage loss and sufficient support. Bootstrap top-K is recomputed for each sampled population; user multiplicities preserve all their cards. Quarter/month and time-block diagnostics expose drift. The two predeclared soft-minus-hard family ablations use 97.5% intervals (Bonferroni allocation across two comparisons); all other ablations are descriptive. No claim of real-bank effectiveness follows from synthetic results.

Ranking is the output, with 2% and 5% sensitivities. No calibrated fraud probability or live payment decision is produced. Common eligibility, ties, source-wide exclusions, unscored fraud and AP conventions match v1. Before final scoring, the selected model must pass import/feature parity, model serialization, explanation arithmetic and a bounded persistence feasibility check. Selection freezes before diagnostics are used to describe mistakes; those diagnostics do not trigger new v2 features.

Development mistakes will be summarized by channel, history/category support and quarter, with missed fraud and false reviews kept distinct. The diagnosis can suggest a subsequent experiment but cannot turn reserved observations into validation. Relationships and new external data remain outside this experiment.

The supported demo is precise-time IBM synthetic USD standalone purchase attempts, with exact MCC/channel and available full warm-up. Date-only, linked lifecycles, arbitrary external datasets, missing channels and truncated-history equivalence remain unsupported. A successful offline gate establishes a candidate for application integration; it does not establish clean-checkout runtime delivery, saved learned contracts or UI acceptance. Existing rule/simulator behavior and personal planning files remain unchanged.

Before reserved scoring, a Windows joblib worker-cleanup error during completed EBM fits was addressed by using two threads for future EBM fitting. The estimator configuration and feature definitions were unchanged. A complete 680,574-row refit of the selected model reproduced its term tables and all 51,889 checked development scores exactly; `execution-parity.json` records both training-source checkpoints. Original fitted artifacts are retained. The final scoring manifest records the corrected execution code. This is a runtime/reproducibility repair, not additional model selection.

Segment tables rerank within each segment at 1%/2%/5% capacity. A separate global-budget breakdown counts detections, missed fraud and false reviews under the single whole-year 1% queue; these answer different questions and must not be conflated.
