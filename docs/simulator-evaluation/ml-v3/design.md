# V3 frozen small-experiment and confirmation design

This experiment asks whether a modest new method improves on the v2 EBM recipe and standard CatBoost. It reuses the immutable v2 feature cache and IBM source; neither the v1/v2 implementation nor their frozen results change.

Three fixed hypotheses are tested: (1) weight fraud examples 20 times as heavily when fitting the same EBM, (2) increase that EBM from 256 rounds/five interactions to 1,024 rounds/ten interactions, and (3) equally average the original EBM and standard CatBoost raw logits. There is no blending-weight search, automatic tuning or test-dependent feature change. Raw logits and their averages are ranking scores, not validated probabilities. EBM settings and sample weights are supported by the [official API](https://interpret.ml/docs/python/api/ExplainableBoostingClassifier.html); parameter values here are hypotheses rather than recommendations from that source.

Small experiments fit July–December 2018 using a deterministic quarter of existing fit users, then screen January–June 2019 on a disjoint deterministic quarter of fit users. Every method uses identical training rows and screening rows, with two fixed seeds. No validation-role or reserved-role user participates. Label-blind user hashing samples complete histories, without undersampling legitimate transactions or removing hard negatives.

The incumbent is the v2 soft-history EBM recipe refitted on the same allowed rows, not the old model trained on a different cohort. Standard CatBoost uses its fixed v2-selected configuration. The three alternatives are screened together. To advance, a candidate must improve pooled recall over the incumbent for both seeds, average at least two percentage points more recall, and avoid average-precision point regression on average. Eligible candidates rank by average quarterly recall across seeds, worst quarterly recall, then average quarterly AP. Exactly one nominee advances; if none qualify, the experiment stops without consuming confirmation outcomes. Screening results are exploratory, not significance claims.

Confirmation uses full-year 2019 **validation-role** users. V2's audit already exposed this cohort's aggregate positive support (270 labels across 28 users), but no candidate performance on these transactions was evaluated. These users' earlier observations participated in past v1/v2 development; this is fresh transaction-level confirmation within a previously used synthetic source, not a never-seen-user claim. All v3 fitting excludes these users. The consumed 2019 **reserved-role** population is never used to tune, choose or confirm this round. Auditing existing source support is not a new experiment result.

Final fitting expands to all fit-role users in July–December 2018, with the same rows for the nominee and both baselines. Candidate identity and all configurations freeze before this fit. Development-only serialization and native explanation reconstruction checks must pass. Save all confirmation predictions, model hashes, protocol and source implementation before joining confirmation labels. No result-dependent refit, nominee replacement or test-window extension is allowed.

Confirmation requires at least 100 frauds across 20 users, at least two percentage points of recall gain at the same top-1% review capacity against **both** baselines, strictly positive paired user-bootstrap lower bounds and no AP/coverage point regression against either. Each of the two prespecified comparisons uses a 97.5% interval (Bonferroni allocation), 2,000 replicates, recomputed weighted top-K and the same sampled users for all models. Report month-block sensitivity, 2%/5% budgets, channel support and exclusions; do not change the primary gate after seeing them. If the nominee fails, retain v2 as the incumbent. A failed gate is an evaluated negative result, not authorization for another search on the same confirmation data.

Training is sequential with two threads and a 2.5 GiB process-memory limit. Dependencies, historical features, existing API/UI behavior and personal planning documents remain unchanged. Statistical success would nominate the method for the already-pending application integration; it does not release a new runtime model. Preserve exact model-output explanations for an accepted single model or algebraically weighted contributions for a blend. Feature evidence retains v2's historical semantics.
